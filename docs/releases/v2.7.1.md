YSS CLI 2.7.1 固定关联模板 v4.7.1，现役 Profile 为 Spec 与 Backend，JSON envelope 与协议保持 v1。

### 主要变更

WorkBuddy 的唯一项目技能目录改为 `.workbuddy/skills`，运行时标识继续使用 `workbuddy`。新建实例不再分发 `.codebuddy`；旧根不作为运行时入口或发现别名。

已有实例使用显式 `sync` 在同一事务写入新投影、来源锁与 metadata，并逐文件退役旧锁登记且精确基线可核验的旧受管投影。`skills ensure` / `assets ensure` 返回 `SYNC_REQUIRED`，不会隐式迁移。用户私有配置、未登记的个人技能与其他业务文件受保护；修改过的旧受管文件需按冲突决议处理。旧锁、来源或受管声明不可信时先恢复材料，再重新规划。

模板技能生成同时加强身份解析、路径边界和本地修改保护，Backend 组合技能生成使用模板源专用入口。

### 升级

升级程序前保留与实例登记来源一致的旧 CLI。旧目录退役需要完整、可核验的旧基线；以 CLI 2.7.0 / 模板 v4.7.0 的 Spec 实例为例，先导出旧材料。Backend 使用 `--profile backend` 并保存到独立目录；路径均需替换为实际绝对路径，输出须为项目外的新目录/新文件。

```sh
/path/to/yss-2.7.0/yss bundle export --profile spec --out /outside/project/base-spec-4.7.0 --json
yss upgrade --to 2.7.1
# 自定义受管工具目录需加 --tool-root。
yss version --json
yss sync --root /path/to/project --base-bundle /outside/project/base-spec-4.7.0 --plan --out /outside/project/sync-4.7.1.json --json
# 审阅实际变更、冲突和保留项后执行：
yss sync --root /path/to/project --apply --plan-file /outside/project/sync-4.7.1.json --json
yss doctor --root /path/to/project --json
yss skills resolve implement --agent-runtime workbuddy --root /path/to/project --json
```

旧 Bundle 材料保留到应用完成，不能用当前项目文件或新版本 Bundle 替代。遇到来源不匹配、旧锁/受管文件漂移或新路径占用时，先处理实际报告并重新规划；不手工删除用户目录以绕过冲突。程序升级不会自动同步项目模板。用户显式保留的旧文件属于退役例外，不再作为 WorkBuddy 活动技能来源。

Windows x64 核对 `SHA256SUMS` 与 `build-only-checksums.json` 后解压使用。两平台归档的来源与资格绑定见共同校验文件、原生 receipt 和发行门禁文件。
