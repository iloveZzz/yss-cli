## 目标与范围

用户在终端查 Spec、在工作台打开详情，或让 Agent 继续同一任务时，应能定位同一个主 Spec，核对本轮目标、阶段、证据有效性和接下来要做的事。停下本轮工作后，可以回看原因与成果，并在原 Spec 下再次开展验证或交付。

首版统一 CLI 有效查询、工作台列表与详情、Agent 续办及状态建议。第二步增加取消当前目标和重开。两步均使用现有 `yss workbench` 和本机数据目录。主 Spec 或实际作为需求来源的 Issue 正文维护规则与验收，工单平台维护外部执行状态，工作台按实际关联汇总证据。多人跨设备同步、外部平台双向写入和发布操作属于范围外。 [工作台自动跟进](../../workbench.md#自动生命周期跟进) · [外部研发关联](../../workbench.md#工程维护与产品-home)

首轮调研用本机 CLI `3.19.0` 对同一修订下的 15 条登记记录做只读对照。默认查询的 15 条均未标记，有效查询返回 11 条完成、3 条进行中、1 条未标记。这是本机样本，完成指查询返回的进度状态。CLI `query` 的缺省口径仍为 `personal`，工作台 Spec 列表采用有效进度。现有目标按范围和版本登记，完全相同的当前目标会复用原版本。 [CLI 查询](../../cli-help.md#个人-spec-工作台) · [工作台列表](../../workbench.md#自动生命周期跟进) · [目标版本规则](../../../src/workbench/progress.rs#L924)

## 已确认决定

2026-11-28，用户对本次澄清 Q1–Q3 答复「三项同意」。

| 决定 | 采用的行为 | 规则 |
| --- | --- | --- |
| Q1 · 未设置目标 | 统一入口显示「未设置本轮目标」，仍可核对内容状态与材料。只读查看不自动建目标。旧个人标记可通过兼容查询读取。 | FR-01、FR-02 |
| Q2 · 取消目标 | 结束本轮，保存原因与已取得的成果。正在运行的已知作业仍按各自入口处理。迟到结果归属原轮，原轮保持已取消。 | FR-05 |
| Q3 · 同范围重开 | 沿用原 Spec 开启独立新轮次，旧成果与结论可回查。经核实仍适用的旧证据可引用，本轮结论按本轮范围与证据重新判定。 | FR-06 |

## 首版规则

### FR-01 统一查询和续办口径

CLI、工作台和 Agent 对同一个数据目录、Spec 和核验快照采用同一套判定。工作台列表、详情、CLI 有效查询和续办文本应一致表达目标终点、当前有效阶段、进度、证据有效性和关注项。详情与状态查询可展开按工程记录的阶段进展、证据来源、核验时间和历史。状态建议同时交代当前观察结果和建议动作。建议补证、同步、复核或解除阻塞时，给出适用阶段、可定位的受影响工程和原因。多个工程并行时，整体进行中仍可同时存在局部阻塞。查询和续办文本提供当时所读事实，执行者在采用建议写入前重新核对目标和证据。

生命周期用法通过现有 `query --entity spec --progress-basis effective`、`spec-status`、`lifecycle-status`、`recommend-status`、`lifecycle` 和 `request` 接续。旧 `query` 的缺省模式和显式 `personal` 模式保留原有顶层个人状态、阶段及其筛选含义。`lifecycle` 的个人阶段历史仍可读取，有效阶段从 `result.progress.stages` 取得。CLI 帮助、模板教程和 Agent 上报说明使用有效查询示例，沿用原 `--data-dir` 和登记返回的 Spec ID。只知道标题或路径时，先用 `--activity all --include-closed` 查找已登记候选，再用工程根及主文件相对路径核对。仍有多个候选时列出差异，等执行者确定身份后再生成续办内容。 [命令说明](../../cli-help.md#个人-spec-工作台) · [状态推荐实现](../../../src/workbench/status.rs#L128) · [模板进度上报](https://github.com/iloveZzz/yss-spec-project-template/blob/59dc25d307929037e09566270158bf9221880899/.template-spec/agents/workbench-progress.md)

终端 `request`、详情「查看 Agent 续办文本」及其复制结果都体现本次读取的有效进度。复制前重读，版本变化时更新预览并标明变化，重读失败时反馈原因。Pi 续接按准备本轮执行时核对的目标、版本和实际选用阶段标注上下文。已排队、运行中及已结束作业可按它们实际绑定或计划采用的轮次回看。发送时发现轮次或版本变化，沿现有启动与续接规则反馈并保留本次输入和原作业绑定。缺少目标时，仍可沿已有权限续办无需绑定阶段的规格内容工作。 [工作台续办读取](../../../src/workbench/service.rs#L150) · [目标与 Agent 绑定](../../../src/workbench/progress_agent.rs#L48)

### FR-02 交代目标缺失与来源异常

已登记的 Spec 缺少目标时，列表、详情、CLI 有效查询和 Agent 续办显示「未设置本轮目标」。用户仍可读取得到的正文、原型、内容状态和历史。原检查记录及个人阶段标记保留各自的含义，该 Spec 不命中有效进度的「进行中」或「已完成」筛选。推荐可提示登记目标。只读查询、打开详情和生成续办文本均不登记目标或记入确认。

「未设置本轮目标」需要能读到登记记录并确认目标为空。登记找不到时提示核对数据目录、工程和 Spec 身份。等待首次核验时显示待核实。核验失败时说明原因和重试入口，可展示上次结果及其核验时间。查询时点、证据核验时间和材料修改时间按各自含义展示。登记已停用时给出恢复入口，实际来源不可读或内容无法解析时指出对应文件及修复动作。若同时已知目标为空，仍可显示该事实，建议动作优先处理停用或来源问题。只有数据可读、登记启用且采用材料可核对时，才建议设置目标。状态查询仍提供可核实的信息。当前主 Spec 无法读取时，续办入口提示恢复来源并重新读取，历史正文仍按历史材料查阅。诊断后的刷新或重试使用只读查询。已有「重新核实」入口按其现有行为可保存自动确认。 [状态查询和建议](../../../src/workbench/status.rs#L128) · [只读与写入入口](../../cli-help.md#个人-spec-工作台)

### FR-03 按本轮范围推进及自动核实

目标明确本轮采用的 Spec 范围及版本、参与工程、适用阶段、验收引用和完成终点。终点继续支持本地实现、合并及指定环境验证。八阶段按实际范围采用，可并行或按原规则标明不适用。阶段进度和证据有效性分别展示。

当前证据充分时，沿用已有自动规则确认规格阶段、验证和本轮结果，并标明「YSS 自动核实」。证据核对实际目标、版本及验收引用。不同工程的局部检查分别留存，合并和环境结果关联实际候选或运行组合。缺证、失败、冲突或过期时显示原因及处理入口。当前轮次和目标版本的明确人工退回优先，更换报告 ID 或补齐证据后仍保留该退回。用户作出新的明确决定并通过核对后，才更新对应阶段的确认结果。业务规则选择、主 Spec 内容确认及业务验收的真实决定保留实际出处。 [自动跟进与人工决定](../../workbench.md#自动生命周期跟进) · [证据范围核对](../../../src/workbench/progress.rs#L2465)

### FR-04 保留已验收历史并提示变化

已人工验收的目标保留当时的完成事实、范围、时间和证据。同一轮仍为当前目标时，主 Spec 出现新版本、共用依赖影响尚未核实或工程证据过期，仅更新当前材料和受影响阶段的提醒。用户可按提醒查到有待办的已完成记录，并在详情查看原验收。自动核实的结论在证据失效后退出当前有效状态。该轮显示待处理的证据及复核动作，原结论仍可回查。刷新或发现材料变化只重新核验适用性，下一轮由明确的登记或重开动作建立。 [既有确认设计](../../plans/2026-11-23-workbench-spec-confirmation-design.md#显示已交付目标与新的工作) · [自动跟进与历史](../../workbench.md#自动生命周期跟进)

## 第二步规则

### FR-05 取消当前目标

有该本机工作台写入权限的用户可从 Spec 详情或 CLI 取消尚未结束的当前目标，或从已完成、已取消的当前目标开启新一轮。Agent 提交相应写入时须有本次操作授权。取消动作指定实际 Spec 与当前轮次，记录非空原因、操作来源和时间。成功后显示「已取消」，保留原范围、成果、检查和答复。当前所展示轮次为已取消时，可用终态筛选定位该 Spec。默认活动列表继续按现有规则隐藏终态。此前已结束的轮次通过详情历史查看。取消目标保持 Spec 登记启用状态原样。

工作台列出当前已知仍在运行的本机与外部作业及已有处理入口，状态不可读的作业显示未知。取消目标后，停止 Agent 作业、取消 CI、关闭工单和处理工程文件仍通过各自入口进行。

取消后，续办该轮可查看原材料与作业，新的阶段工作须绑定可推进的目标。作业、上报和已关联的远端执行凭证按启动或上报时的绑定核对归属。能核对原轮和来源的迟到结果留在原轮历史，保留当时版本。旧输入现已不可复核时，标明该限制。接收迟到结果只补充历史，已取消的状态和新轮进度、阻塞、证据有效性、核验时间及确认均保持原样。只能确认 PR/MR 或 CI 在平台上的状态时，显示所读到的平台状态。核对其适用轮次和范围后，该观察才可参与阶段进度判定。相同 Spec 内容、提交或环境仍可能对应多个轮次，复用证据须符合 FR-06。 [既有作业行为](../../workbench.md#在工作台运行-pi-agent) · [现有外部状态上报](../../../src/workbench/progress_tracking.rs#L233)

### FR-06 同一 Spec 下重开一轮

开启新一轮前核对本次采用的 Spec 版本、范围、终点和参与工程，并能辨认作为起点的已完成或已取消轮次。即使这些输入与历史完全相同，也以可单独识别的轮次记录本次工作，沿用原 Spec ID。工作台切换到新轮次，历史仍可查看原时间、原因、成果和结论。资料 `register` 仍用于登记或刷新 Spec，既有 `progress set-goal` 的登记、版本更新及相同输入重试沿用原含义，重开有自己的明确动作。 [现有目标登记](../../../src/workbench/progress.rs#L924)

新轮次按自己的范围和证据显示进度。可引用的旧证据须核对其实际覆盖的验收项、相关输入和参与工程版本。涉及联调、合并和环境验证时，核对实际候选组合及环境。采用时记录原报告和核实依据，覆盖不明时显示待核实。前一轮的完成、取消、确认及退回只归属产生这些记录的轮次，已经保存的主 Spec 内容确认及业务答复仍按原有适用范围核对。 [既有证据复用规则](../../plans/2026-11-23-workbench-spec-confirmation-design.md#以验收所用范围判断证据)

### FR-07 处理重复请求和并发变化

取消与重开复用工作台已有的写入权限、目标身份核对及幂等回执。相同请求 ID 和原输入返回原操作回执，即使此后已经换轮。用同一 ID 提交不同内容时提示冲突。回执描述该次操作，当前状态须以重新读取的轮次为准。请求超时时保留输入和原请求 ID，显示「结果待核对」。优先取回回执，需重试时沿用原请求 ID 与输入。当前状态变化而无法关联该次操作时，仍标明结果未知。 [既有写入约定](../../cli-help.md#上报生命周期进展) · [回执复用](../../../src/workbench/service.rs#L406)

首次写入时核对权限、当前轮次、目标版本和动作所需的有效状态。自动确认已经失效的轮次按当前待处理状态核对，历史确认可查。同一 Spec 同时只推进一个当前目标轮次。完成与取消竞争时，以首先成功保存的状态为准。完成先保存则拒绝待提交的取消，取消先保存则后到的人工确认或自动核实无法改变已取消状态。对同一个已结束轮次并发发起两次独立重开，先成功的一次产生新轮次。另一请求提示轮次已变化并保留输入，重新读取后可选择下一步。

## 交互方案

工作台沿用「Spec」列表、详情「生命周期」和「目标结果确认」。终端沿用 `yss workbench`，Agent 从现有续办入口取得目标和证据。下表描述可观察的入口及反馈。

| 入口或条件 | 用户动作与反馈 | 规则 |
| --- | --- | --- |
| Spec 列表、详情或 CLI 有效查询 | 找到原 Spec，查看本轮终点、阶段、有效性和关注项。从「需复核」摘要进入详情时定位并聚焦对应诊断，返回列表保留筛选。状态和失败原因有文字说明。 | FR-01、FR-04 |
| 已登记但未设置目标 | 显示「未设置本轮目标」，可读取正文、原型或内容状态。有写权限时可沿已有目标登记入口明确发起。 | FR-02 |
| Agent 续办及状态建议 | 给出本轮范围、采用版本、缺口及下一步。出现局部阻塞时说明受影响工程，其他独立工作仍可继续。续办重读和复制操作给出文字反馈。 | FR-01、FR-03 |
| 当前尚未结束的目标 | 选择「取消本轮」，核对目标和已知运行作业，填写原因后提交。空白原因提示在字段处。提交前退出保持目标原样。明确保存失败时保留输入并说明原因。结果未知时按 FR-07 核对。 | FR-05、FR-07 |
| 已完成或已取消的目标 | 选择「开启新一轮」，核对采用版本、范围、终点与参与工程。成功后显示新轮次，保留原轮次的历史入口。未获写入权限时仅提供读取，提交也按实际权限核对。 | FR-06、FR-07 |

取消和开启新一轮可通过键盘进入、填写和提交。打开确认交互时，焦点落在可阅读目标或开始输入的位置。提交前可按 Esc 退出。退出后焦点回到触发入口，入口因状态变化消失时回到目标状态。字段错误与对应输入关联，提交、失败和结果待核对状态以文字提示并可被辅助技术读取。

## 验收场景

| 编号 | 前提与操作 | 可观察结果 |
| --- | --- | --- |
| AC-01 · FR-01 | 固定材料和工程版本，准备同名但位于不同工程的两条登记。其中一条旧个人状态为已完成，有效状态为进行中。在选定目录中查询全部候选并核对路径，对同一条记录检查工作台、CLI 有效查询及状态命令，比较默认和显式个人查询，包括关闭项。 | 路径和工程可区分。有效入口对同一核验结果展示一致的目标、阶段、进度和有效性。旧查询以原个人状态匹配筛选，旧收藏保留原有筛选和排序。 |
| AC-02 · FR-02 | 准备从未设目标、旧个人状态为进行中或已完成的 Spec，分别使用草稿、就绪和已确认的内容状态，保留可读原型和旧检查。查询后再用不存在的 Spec ID 对照。 | 已登记项显示「未设置本轮目标」，保留已核实的内容和材料。「进行中」和「已完成」有效筛选均不命中。只读查询及无需绑定阶段的内容续办不新建目标或确认。不存在的 ID 提示登记未找到。 |
| AC-03 · FR-01、FR-03 | 前端仍在执行，后端明确阻塞。核对建议后补齐本轮有效凭证并观察自动确认。另设验证阶段人工退回，换报告 ID 重报并补证，再保存明确且经核对的新人工决定。 | 整体进行中与后端阻塞并列，建议指出后端、阶段、原因和处理动作。证据满足且无有效退回时自动确认。换 ID 或补证不绕过退回，新的有效人工决定仅更新对应阶段，历史可查。 |
| AC-04 · FR-03、FR-04 | 分别核对以本地实现、合并和指定环境验证为终点的目标。另测某环境的证据绑定到了不同候选，以及自动确认后相关输入发生变化。 | 每个目标只按选定终点及对应证据判断。环境或候选不匹配时给出补证原因。过期自动确认退出当前结果并可在历史查看。 |
| AC-05 · FR-01、FR-04 | 当前目标有真实人工验收，此后主 Spec 实质修改或后端证据过期，尚未开启新轮。用键盘从「新版待确认」或「需复核」结果进入详情，再返回列表。 | 目标仍为已完成，当前提醒可定位并聚焦受影响材料或工程阶段。建议指出范围和下一步。可查看原验收，返回保留原筛选。 |
| AC-06 · FR-05、FR-06 | A 轮已有前端成果，后端 Agent 作业和 CI 正在运行。取消 A。收一份 A 的报告，再按相同范围开启尚无后端报告的 B。B 开启后分别重放 A 的迟到阻塞、CI 成功和失败，并加入一条仅能读到平台状态的观察。另将工程换版，先核验并记录 B，再收 A 的迟到报告。 | 取消时可查看已知作业和各自入口。已知归属与来源的结果留在 A，旧输入无法复核时有提示。A 保持已取消，接收迟到结果前后 B 的有效阶段、阻塞、证据、核验时间和确认一致。归属未知的观察仅反映原平台状态。 |
| AC-07 · FR-06 | 分别从已完成及已取消的目标按相同输入开启新一轮。查看原报告但暂不采用，再核实引用覆盖当前 AC 的旧报告，另尝试引用旧环境或候选不符的报告。 | Spec ID 保持，两个轮次可区分。查看旧报告不改变本轮。已核实的引用可参与本轮判定，环境或候选不符时显示缺口。旧确认和退回仍可从原轮追溯。 |
| AC-08 · FR-07 | 分别让同轮完成先于取消提交、取消先于人工确认或自动核实、两个不同请求同时从同一已结束轮次重开。保留两处入口最初所见状态。 | 第一种保持完成并提示取消已不适用，第二种保持取消，第三种只产生一个新轮次。冲突方收到变化说明，输入仍可取回。 |
| AC-09 · FR-01、FR-02 | 等待首次核验。取得有效结果后中断读取或移开主 Spec，尝试通过 CLI 和工作台读状态及续办。恢复来源后用只读刷新或重试。 | 等待及失败时标明读取状态，仍可识别上次结果的时间。可核对的无目标事实与来源诊断分开。续办读取失败提示恢复来源，恢复后采用当前正文，目标及确认记录保持一致。 |
| AC-10 · FR-01 | 对同一 Spec 比较终端 `request`、详情预览和实际复制的续办内容。预览后换目标或改稿再复制。Pi 续接提交前再更换目标。 | 复制取当前核验结果并反馈变化。受影响的 Pi 续接说明冲突，保留输入以便重新核对。正常续接能看清实际目标、版本及阶段，已有作业继续对应原绑定。 |
| AC-11 · FR-05 至 FR-07 | 从无写入权限的会话试取消或重开。再用有权限会话以键盘打开取消确认，分别测试空白原因、提交前退出、失败重试及成功后原触发入口消失。 | 无权限的动作未生效并说明原因。空白原因关联到输入，退出保持轮次原样，失败保留输入，提示可读。关闭后焦点回到入口或目标状态。 |
| AC-12 · FR-07 | 本次写入提交后、回执返回前断开。此后切换到另一轮，沿原请求 ID 重发原输入，再用同一 ID 改原因或版本。另测尚无回执且当前状态变化的查询。 | 原输入返回原回执，另行读取可见当前轮次。同 ID 改内容提示冲突。尚无依据判明时明确结果待核对，续办不产生重复动作。 |

首版可用一条本机单工程 Spec 和一条已有跨工程 Spec 核对 AC-01 至 AC-05、AC-09、AC-10。第二步使用独立数据目录核对 AC-06 至 AC-08、AC-11、AC-12。命令别名、返回字段及持久化方案由研发依据可观察结果确定。本稿为文字设计，已按上述场景推演。可操作原型、候选程序及辅助技术运行结果待验证。
