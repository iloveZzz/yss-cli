# 工作台 Issues 查询与阅读交互说明

[打开本地原型](../../../prototypes/2026-11-28-workbench-issues/dist/index.html)。本说明配合[主规格与验收](./2026-11-28-workbench-issues-spec.md)阅读。原型使用可重复的本地样例模拟 GitHub 和 GitLab 的返回。“在原平台打开”是访问外部网页的入口。样例的仓库、编号和目标链接对应公开 Issue，界面中的中文内容、时间、状态和标签用于演示，可能与原站不同。

## 从搜索到阅读

| 位置 | 操作与反馈 | 对应验收 |
| --- | --- | --- |
| Issues 入口与来源 | 侧栏定位当前页面。先核对当前工程、平台和仓库路径，再选择来源。切换来源时保留已提交的查询和状态，从第一页显示新来源。 | AC-01、AC-03 |
| 搜索与筛选 | 输入关键词后按 Enter 或执行搜索。输入完整的 `#编号` 精确定位。状态筛选立即生效，清空搜索可继续浏览。列表区明确当前状态、仓库、编号和翻页位置。 | AC-02、AC-03、AC-04 |
| 详情抽屉 | 点击行或用键盘打开标题，从右侧打开详情。顶部显示来源、编号和标题，关闭入口持续可用。抽屉内容独立滚动，正文可切换预览或原文。遇到外部附件可从原站继续。 | AC-05、AC-08 |
| 关闭详情 | 点击关闭按钮、在遮罩露出时点击遮罩，或按 Esc。打开和关闭详情沿用同一列表地址，保留查询、来源、筛选、页码和滚动位置。焦点回到刚才打开的 Issue 标题，原条目已不可见时回到列表可用位置。后续条件变更重置页码。 | AC-04 |
| 查询异常 | 零匹配时调整关键词或状态。服务失败时保留条件，恢复连接后重试。服务仅返回部分结果时，提示缩小范围。无来源时提示核对工程配置。 | AC-01、AC-06 |
| 访问变化 | 已读过列表，打开详情时发现当前账号已失去来源访问权限，应收起正文与该来源的旧结果，并在抽屉提示原因和恢复方式。抽屉仍可关闭。仅单条记录不可用时，其他可读结果保留。 | AC-07 |

## 样例边界

- 样例使用固定内容、模拟分页和可重复触发的异常。演示用于核对浏览、筛选、正文阅读和恢复行为。真实账号访问、企业实例、远端检索索引和访问变更仍需在产品实现时验证。
- Markdown 的任务复选框用于阅读已完成和待办项。原文切换保留作者输入，在原平台访问附件或阅读平台特有内容。列表和详情均没有新建、编辑或改状态的操作。

## 可重复的试读路径

1. **确认来源并跨页搜索正文。** 展开「切换来源」，可核对「桌面编辑器」以 Issue 跟踪配置选择 `microsoft/vscode`，其模拟工程代码仓为 `microsoft/vscode-docs`。在 GitHub 的 `microsoft/vscode` 使用默认开放状态。在第一页搜索「干净的环境」，命中 `#3 Linux 安装包缺少语言服务`。这句话只出现在正文，该条原先位于后续页。在抽屉核对正文，关闭后再清空搜索。
2. **同号与状态。** 搜索 `#8` 先打开 GitHub 的「打开工作区时编辑器短暂闪屏」，关闭抽屉后切到 GitLab 的 `gitlab-org/gitlab`。同一查询现在命中「校验 LDAP 的 SSH 密钥同步设置」。改查已关闭时没有匹配，改查全部后恢复结果。
3. **核对格式。** 在 GitHub 的 `#8` 查看「观察记录」表格、设置代码、勾选状态，以及观察笔记和首帧图片的处理。切到原文，对照 Markdown 标记。GitLab 的 `#8` 带有平台附件，GitHub 的 `#5` 则用于检查空正文。
4. **继续浏览。** 在 GitHub 清空条件，进入后一页并滚动列表。聚焦一条结果标题，按 Enter 打开抽屉，切换到原文并滚动阅读。按 Esc 后，核对还在原页和原滚动位置，焦点回到原标题。再分别用关闭按钮和遮罩复验。窄屏重复打开、滚动和关闭。
5. **区分零匹配与结果不全。** 在右上角「演示场景」选「部分结果」，可继续打开已读条目。输入一个不匹配的词，查看只针对已读范围的提示。切回「正常读取」，同一词返回完整查询的零匹配提示。
6. **重试与撤权。** 在列表提交 `#8` 后选「网络失败」，点「重试读取」，确认搜索框及结果恢复。打开 `#8`，然后在抽屉顶部的「演示场景」选择「仓库权限不足」。确认旧标题、正文和原站链接都已收起。关闭抽屉，核对该来源的旧条目也已收起，再用「重新检查权限」模拟恢复。另可在无关键词的列表选择「单条详情不可用」，再打开一条记录。关闭后仅这条记录收起，其他条目仍可阅读。选择「无可用来源」可检查来源缺失提示。用「演示场景 → 正常读取」恢复样例。

演示菜单仅供评审。每页五条便于复现跨页操作。这个数量不规定正式页面的分页大小。

## 查看与复建

可直接在浏览器打开单文件原型，使用「在 GitHub 打开」或「在 GitLab 打开」前往对应的公开记录。若以后使用工作台内嵌资源预览，宿主限制弹出新窗口。可单独打开本地 HTML 体验原站跳转。需要从源码复建时，在 `yss-cli` 仓库根目录执行以下命令，再打开同一入口。

```sh
pnpm --dir ui install --frozen-lockfile
node prototypes/2026-11-28-workbench-issues/build.mjs
```

## 验证范围

2026-11-28 在本机 Chrome 打开重新构建的单文件，验证 1320 像素桌面显示右侧抽屉，390 和 320 像素窄屏占满宽度。标题、关闭按钮和原站入口不随正文滚动。验证关闭按钮、Esc 和桌面遮罩三种关闭方式，以及打开时将焦点放在标题、Tab 焦点留在抽屉内、关闭后回到第二页的原行和原滚动位置。打开、关闭前后列表地址与浏览历史一致。

同时回归了后续页正文命中、GitHub 和 GitLab 同号、Markdown 预览与原文、空正文、模拟仓库撤权、单条不可用与重试。原行收起后焦点回到搜索框。

真实网络响应乱序、账号撤权生效时点、私有附件的原站访问，以及来源配置变更的识别，留给接入真实平台后的验收。原型用固定来源、样例数据和场景切换来演示这些规则中的可见反馈。
