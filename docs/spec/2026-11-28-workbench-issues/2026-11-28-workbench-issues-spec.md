## 目标与范围

工程协作者收到一个 Issue 编号，或只记得正文里的一句话时，可以在 YSS 工作台找到对应记录、读懂其格式化正文，并返回原来的搜索位置。首版的“管理”按用户在 2026-11-28 本次对话中的选择，覆盖**查询、筛选和阅读**。新建、编辑、评论、关闭、重开以及勾选远端任务项均在范围外。本页只读取当前账号已有权限可见的内容。

现有「研发关联」适合给工程或 Spec 关联一个已知编号，只展示远端摘要。新入口面向尚未关联的 Issue，查询无需先选择 Spec，打开结果也不会新增研发关联。「合并请求」是并列入口，仍负责 GitHub PR 和 GitLab MR。两个页面沿用相同的工作台导航、来源标识和详情抽屉交互。Issues 支持在整个选定仓库内检索正文和按项目内编号阅读。[工作台与研发关联](../../workbench.md) · [合并请求浏览规格](../2026-11-27-merge-requests/2026-11-27-merge-requests-spec.md)

## 功能规则

| 编号 | 场景 | 页面行为 |
| --- | --- | --- |
| FR-01 | 确定查询范围 | 从侧栏「Issues」进入，当前范围同时标明工程、平台和跟踪仓库。一次查询一个来源。有明确配置时使用该工程的 Issue 跟踪仓库，即使它与代码仓不同。无明确配置时，可采用工程唯一可识别的远端仓库。存在冲突或身份不明时，提示核对来源。配置的仓库暂时无权访问时，保留来源并提示原因，避免静默切换到代码仓。实例不同的同名仓库应可区分。 |
| FR-02 | 浏览列表 | 默认查看当前来源的开放 Issue，可切换已关闭或全部。按最近更新时间从新到旧显示标题、仓库内编号、状态、标签（如有）和更新时间。来源始终可见。两端都显示 `#编号`。GitHub PR、GitLab MR 不作为 Issue 结果出现。 |
| FR-03 | 精确查找或检索 | 提交普通关键词时，平台在所选仓库的**标题或正文**中查找，范围跨越列表所有页。纯 `#` 加正整数按仓库内编号定位。编号相同且仓库不同，代表不同条目。两种查询均受当前状态筛选约束。清空并提交后恢复该来源和状态下的列表。评论、代码和附件内容不纳入关键词范围。 |
| FR-04 | 翻页与保留列表位置 | 服务仍有结果时可翻页。新查询、切来源或切状态从第一页开始。切来源保留已提交的关键词和状态，便于跨仓核对同号。详情抽屉打开期间保留列表地址、浏览器历史、查询条件、页码和滚动位置。关闭后，键盘焦点回到打开抽屉的结果标题。该结果已不可见时，焦点转到当前列表的可用位置。较早请求晚到时，页面仅展示当前条件对应的结果。 |
| FR-05 | 在抽屉内阅读 Markdown | 点击列表行或用键盘打开结果标题，从右侧打开详情抽屉。抽屉顶部显示来源、编号、标题和关闭入口。正文在抽屉内部滚动。可点击关闭按钮或遮罩，也可按 Esc 关闭。窄屏可在抽屉内阅读并关闭。默认展示 Markdown 排版，可切换原文、打开原平台。保留标题层级、段落、列表、引用、表格、代码缩进和换行。任务项呈现勾选状态且只读。正文为空时提示该 Issue 没有正文。站外网页链接可打开。仓库相对链接、附件或平台专有语法无法可靠还原时，提供可理解的提示、原文或原平台入口，避免误开本地文件。远端原始 HTML 作为文本安全展示。 |
| FR-06 | 处理空结果、失败与权限变化 | 无来源、当前条件零匹配、读取失败和结果不完整应有各自反馈。失败保留来源、条件与恢复操作。已知结果不完整时标明覆盖限制，允许收窄条件。列表成功后详情读取仍取决于当前访问权限。权限失效、条目已移除或平台无法区分二者时，收起受影响的内容，在抽屉内提示重新核对访问，仍可关闭抽屉。一次失败不能成为“仓库没有 Issue”的依据。 |

## 验收场景

| 编号 | 给定条件与操作 | 可观察结果 |
| --- | --- | --- |
| AC-01 · 来源 | 工程的代码托管仓库与 Issue 跟踪仓库不同，进入「Issues」。再切到另一个平台的来源。 | 来源标明工程所用跟踪仓库。列表、详情和原站入口均属所选仓库。来源不可用时显示原因。对应 FR-01、FR-06。 |
| AC-02 · 正文命中 | 一条开放 Issue 位于后续页，标题没有关键词，正文含关键词。从第一页提交该关键词。 | 能在结果中找到该条目，打开后能在正文读到关键词。清空并提交，恢复开放列表。在任选状态组合下，PR/MR 不出现在结果里。对应 FR-02、FR-03。 |
| AC-03 · 同号和状态 | 在来源 A 输入 `#编号`，切换至同样存在该编号的来源 B。再切换到排除其状态的筛选。 | 两次命中各自仓库的 Issue。排除该状态后显示当前条件无结果，切回「全部」后重新命中。对应 FR-02、FR-03、FR-04。 |
| AC-04 · 关闭抽屉回到原位 | 在第二页滚动列表，再用键盘打开一条 Issue 并切换 Markdown 原文。分别通过 Esc、关闭按钮和遮罩关闭抽屉。随后从该页提交新关键词。 | 抽屉从右侧打开，列表地址和浏览器历史保持原样。关闭后可在原来源、原查询、原筛选和原页码的原位置继续浏览，焦点回到原结果标题。新查询从第一页开始。快速切换来源或条件后，晚到结果不覆盖当前查询。对应 FR-04、FR-05。 |
| AC-05 · 抽屉内正文阅读 | 在桌面和窄屏分别打开正文含标题、列表、表格、代码、任务项与链接的 Issue，再核对空正文样例。滚动抽屉并切换预览与原文。 | 正文在抽屉内滚动，顶部标题和关闭入口始终可用。格式可辨，代码保留换行，原文保留 Markdown 标记。点击任务项不会更改远端状态。空正文可识别且仍能打开原站。包含 HTML 标记或平台附件的正文可以继续阅读。对应 FR-05。 |
| AC-06 · 检索受限 | 分别让远端返回不完整结果、查询失败和成功零匹配，然后收窄条件或重试。 | 不完整时可读已返回的结果并看到限制提示。失败保留查询供重试。成功零匹配显示当前条件下的空态。对应 FR-03、FR-06。 |
| AC-07 · 权限变化 | 有权限时取得列表，打开详情前远端撤销访问或移除该 Issue。 | 正文不可见，抽屉提示条目不可用或访问受限，可关闭后核对来源。若仅该条目不可用，收起其旧内容，其他可读条目仍可浏览。若已知失去整个仓库的权限，同一来源旧结果也应收起。对应 FR-01、FR-06。 |
| AC-08 · 只读边界 | 持有远端写权限的成员完成搜索、翻页、打开抽屉、切换原文并关闭抽屉。 | 工作台不提供远端写操作，Issue 的标题、正文、任务项和状态保持原值，也不会自动创建研发关联。对应 FR-01、FR-05。 |

## 决定与核验依据

- **OQ-01 已获业务答复。** 用户选择「首版只做查询、筛选和阅读（建议）」。此决定适用于本页的操作范围。用户随后明确要求沿用「合并请求」菜单的交互，通过抽屉打开 Issue。默认开放状态、一次查看一个来源及附件降级方式供评审。业务规格与验收、原型与交互均待用户评审。
- **平台依据。** GitHub 的 Issue 列表可能包含 PR。关键词搜索有结果上限，也可能标记结果不完整。GitLab 支持在特定项目的标题和描述中搜索，详情用项目内编号定位。这些差异直接影响 FR-02、FR-03 和 FR-06。[GitHub Issues](https://docs.github.com/en/rest/issues/issues#list-repository-issues) · [GitHub 搜索范围与限制](https://docs.github.com/en/rest/search/search#about-search) · [GitLab 项目 Issues](https://docs.gitlab.com/api/issues/#list-all-project-issues)
- **实际样本。** 2026-11-28 对两个平台的公开仓库查询 `markdown`，均找到标题未包含该词、正文包含该词的 Issue。工作台现有渲染函数可将公开样本的标题和代码块转成排版元素。私有仓、企业实例及真实撤权流程须在对应环境核验。[GitHub 正文命中](https://github.com/cli/cli/issues/14618) · [GitHub 排版样本](https://github.com/cli/cli/issues/14407) · [GitLab 样本](https://gitlab.com/gitlab-org/cli/-/work_items/8804) · [工作台 Markdown 渲染](../../../ui/src/views/SpecDetail/schemas/markdown.ts)
