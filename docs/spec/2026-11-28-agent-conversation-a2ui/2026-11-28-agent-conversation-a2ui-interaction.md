# 会话卡片的操作、回看与反馈

本说明对应[《Pi 与 Grok 会话中的交互式回复》](2026-11-28-agent-conversation-a2ui-spec.md)。示例使用虚构的活动报名场景。界面中的 Pi 和 Grok Build 表示两个独立的模拟会话。

直接打开[单文件原型](../../../prototypes/2026-11-28-agent-conversation-a2ui/dist/index.html)。在顶部切换宿主，在会话列表选择「需求澄清」或「方案比较」。窄屏先点左上角的会话列表按钮。若要核对收包异常，打开列表中的恢复示例，逐步接收消息。原型源码及依赖锁文件位于[原型目录](../../../prototypes/2026-11-28-agent-conversation-a2ui/)，在该目录可用 `pnpm install --frozen-lockfile`、`pnpm run build` 重新生成单文件。

## 怎样使用

用户在原会话读到助手回复，卡片出现在相关正文处，输入框仍用于下一轮讨论。澄清场景把问题和可展开的依据放在一起；比较场景让两种方案按相同维度排列。选中的项目有可读标记。在窄屏上按阅读顺序查看相同内容，展开、返回和继续讨论都可用键盘操作。

| 用户动作 | 画面及业务结果 | 对应规则 |
| --- | --- | --- |
| 提问「报名截止后还需要澄清什么」 | 可以看到问题，展开后读到这项问题的依据。回到列表仍在同一条回复；正式 Spec 问题的答复状态保持原样。 | FR-02、FR-04 |
| 询问统一截止和管理员补录的区别 | 同一条比较回复展示两项方案。用户能辨认选中的项，也可改选。选择本身不会触发发送。 | FR-04、FR-06 |
| 明确要求「只用文字」，或指定「请用卡片比较」 | 前者只显示包含方案差异的文字回复；后者显示比较卡。 | FR-05 |
| 已写「请从运营成本考虑」，选「允许管理员补录」，点「继续讨论」 | 原输入之后出现可编辑的所选内容。重复点击时草稿里仍只有一份；用户可以继续修改，显式发送且受理后出现下一轮。 | FR-06 |
| 在「发送回执」示例中选择方案、追加、发送 | 进入待核实状态，保留原轮及草稿，可阅读依据、编辑输入。发送与卡片追加暂停。点「模拟回执：未受理」，可修改草稿后重试；点「模拟回执：已受理」，只新增一轮，显示发送时的文字。核对期间另写的内容仍保留在输入框。 | FR-06、FR-07 |
| 下一轮受理后回看旧卡 | 仍能展开当时的依据。旧卡不提供将内容加入草稿的动作。阅读位置和当前输入均独立于旧卡的展开状态。 | FR-01、FR-07 |
| 在两个宿主或两个浏览器标签间切换 | 草稿按会话保留。在另一标签编辑 Grok 的内容后回到 Pi，其原草稿仍在。若另一标签已在同一会话开启新轮，原卡只供回看。 | FR-01、FR-03、FR-06、FR-07 |
| 打开「消息恢复」，先接收不支持的消息，或在完整卡片后接收无效更新 | 前者只有可读提示，后者保留上一张有效卡。刷新、切换宿主再返回或进入历史，均按当时实际接收的阶段显示。旧轮仍可展开已收到的依据。 | FR-01、FR-07、FR-08 |

## 视觉验收对照

本次采用 YSS 正式工作台 AI Agent 会话作为视觉基线。共用主题给出系统字体、画布与表面材质；会话页定义局部中性色、消息排版、阅读宽度和输入区。两种宿主使用相同的显示规则。依据见[工作台设计规范](../../../ui/DESIGN.md)、[工作台基础样式](../../../ui/src/styles/tokens.css)、[主题映射](../../../ui/src/styles/theme.css)和[会话样式](../../../ui/src/views/PiWorkspace/workspace.css)。

| 对照区域 | 可观察的要求 |
| --- | --- |
| 材质与层级 | 沿用浅色工作台的暖橙与冷蓝背景、半透明面板及卡片层级。以会话局部中性色表达主要操作。模型不能指定任意配色、字体、CSS 或自定义交互控件。 |
| 对话与输入 | 用户消息靠右，助手回复与卡片靠左。主会话的阅读栏与底部输入区对齐，共用桌面最大 736 px 阅读宽度。会话正文采用系统字体，基线为 14 px、行高约 1.68。从执行详情回看时，卡片沿用该详情页自己的消息字号、行距及布局。 |
| 控件与状态 | 使用工作台的 shadcn-vue New York v4 控件和 Lucide 图标。普通卡片操作按钮在桌面高 34 px、圆角 8 px，卡片圆角 12 px；会话输入区沿用 16 px 圆角和圆形发送按钮。选中同时有文字或勾选标记，禁用、键盘焦点及错误反馈均可分辨。 |
| 窄屏与辅助显示 | 在 390 px 和 320 px 视口检查选项堆叠、长文字换行、输入字号 16 px、主要点击区至少 44 × 44 px。键盘可展开、选择、追加并回到草稿。减少透明度、增强对比度或强制颜色时，画布使用实色，面板关闭模糊，选中标记和焦点仍清晰。浏览器缺少模糊支持时使用实色面板。减少动画后操作结果和状态提示仍可见。 |

## 需要研发联调的行为

原型用预设消息模拟两种宿主和发送回执。真实 Pi 的流式增量与最终全文如何合并、Grok 的文本分段何时完整、模型输出与纯文字要求冲突时的回退，以及掉线后的历史、服务端回执、工程权限和执行详情跳回原会话，均需在生产接入后联调。执行详情沿用现有「打开原会话」入口，查看卡片时没有草稿写入动作。

## 已复验的原型路径

2026-11-28 使用本机 Chrome 打开构建后的 HTML，分别在 Pi 和 Grok Build 示例会话中操作。需求澄清能展开依据并追加所选问题；方案比较能改选、追加且连续点击只保留一份。输入「请从运营成本考虑」后追加方案，切换宿主再返回，原文和选择均保留。显式发送后出现第二轮，重新打开页面仍能展开第一轮依据，旧轮没有「继续讨论」入口。显式请求卡片、普通简短提问及纯文字比较分别得到预期形式。

恢复示例已验初始消息不完整、无效消息提示、完整卡片出现、无效增量保留上一有效画面及再次恢复。窄屏复验含 390 × 844 和 320 × 640，两种尺寸均无页面横向溢出。键盘可选择、展开及追加，追加后焦点回到草稿。原型使用固定版本的 A2UI Core 校验本地消息，`pnpm run typecheck` 和 `pnpm run build` 通过。

**视觉复验（AC-09）。** 在 Chrome 中将原型的计算样式与加载正式工作台 CSS 的相同控件对照。1366 px 视口下，比较卡和输入区等宽 736 px；消息正文为 14 px / 23.52 px；普通操作控件高 34 px、圆角 8 px。390 px 和 320 px 下，阅读区两侧各留 12 px，输入字号 16 px，圆形发送按钮为 44 × 44 px。卡片圆角 12 px、输入区圆角 16 px。减少透明度、增强对比度或强制颜色时，浏览器均切换为实色画布与面板，模糊关闭。

向已展示的 A2UI 卡片分别提交带任意 `style`、`class`、`color` 的更新，三项均被拒绝，原画面保留。真实工作台执行详情中的渲染和操作系统原生辅助显示设置仍属产品联调范围。

680 px 视口的发送按钮也按窄屏触控规范保持 44 × 44 px。浏览器模拟「减少动态效果」时，原型按钮计算过渡时长为 0 秒。

本次审查在重新构建的单文件原型上补验了以下反例。

| 复验方式 | 观察结果 |
| --- | --- |
| 分别用两种宿主模拟待核实、刷新、未受理、重试，再在核实前编辑输入 | 待核实期间仍为原轮；未受理保留可编辑草稿。模拟已受理只新增一轮，轮中记录发送时的文字，输入框保留后来输入。 |
| 仅收到无效首包便发送下一轮，重新打开旧轮；另试先有有效卡、再收到无效更新 | 前者回看只有原文和提示；后者保留有效卡和依据。旧版示例未记录收包阶段的，只有留存了选择或展开等证据才恢复卡片。 |
| 在两个标签分别修改 Pi 和 Grok 草稿，刷新；在同一标签给已追加的文字补写半句，再点击同一选项 | 两个会话各自保留草稿，标签各自恢复所在会话。补写的原文保留，未重复追加。 |
| 输入「仅用文字比较这两个方案」及「仅用文字说明活动报名有什么问题需要澄清」 | 均只显示文字，分别可读到方案差异及澄清问题的依据。 |
| 窄屏切换宿主、关闭会话列表；桌面用键盘重新展开会话列表，再缩到手机宽度 | 常用菜单及宿主切换的点击区至少 44 × 44 px。强制颜色下当前宿主和会话有下划线。桌面重开时焦点在当前会话，缩窄隐藏列表后回到菜单入口。 |
