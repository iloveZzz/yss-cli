## 用户目标

工作台用户向 Pi 或 Grok Build 提问后，可以在回复里展开依据、比较选项，把选中的问题或方案带入同一会话继续讨论。首版以需求澄清和方案比较验收。两个宿主使用相同的阅读和操作方式。

本需求衍生自[《Pi Agent 对话与执行工作台》](../2026-11-25-pi-agent-workspace/2026-11-25-pi-agent-workspace-spec.md)。原规格定义了执行轮次、正式问题答复、草稿与成果接收。本规格负责回复正文中的交互及其与这些操作的衔接。

## 业务规则与验收

| 编号 | 业务规则 | 可观察的验收结果 |
| --- | --- | --- |
| FR-01 / AC-01 | 回复属于产生它的会话和轮次。打开另一会话、浏览历史或重新打开页面，沿用现有的来源标识和阅读行为。 | 用户从会话乙回看会话甲的一条交互式回复时，能识别来源。单纯打开该回复不会发起新轮次或登记业务决定。 |
| FR-02 / AC-02 | 讨论中的操作与正式答复各有结果。Pi 已发出的正式业务问题，沿用原规格 FR-04 的提交与保存回执。 | 讨论同一问题时，即使用户在助手正文里选了一个选项，正式问题的已答状态仍以该问题实际保存的回执为准。 |
| FR-03 / AC-03 | 交互沿用所属会话已有的工程授权和续接条件。发起下一轮、接收成果和提交正式答复分别使用对应的工作台动作。 | 同一份内容在 Grok 只读会话中展示后，工程文件保持原样。原会话已不可续接时，工作台给出相应原因，用户可以回看已留存的内容。 |
| FR-04 / AC-04 | 当一个问题需要查看依据或比较多个方案时，回复可展示可操作的选项。需求澄清卡关联问题与依据；比较卡在相同维度列出各方案的区别。 | 两种宿主分别演练「活动报名截止后还能补报吗」：展开某个问题能看到与之对应的依据；比较「统一截止」和「允许管理员补录」后，用户能辨认当前选择。 |
| FR-05 / AC-05 | 用户可以直接要求卡片。未指定形式时，Agent 可在任务适合交互时主动展示，简单问题可用文字。用户明确要求纯文字时，回复仅呈现文字。 | 「这两个方案怎么选」允许主动出现比较卡；「请用卡片比较这两种方案」应展示比较卡；「只用文字比较」只出现文字，其中仍能读到两种方案的差异。 |
| FR-06 / AC-06 | 选中一项可先阅读或更改选择。「继续讨论」将所选的问题或方案追加到当前会话草稿。用户可编辑、删除、补充，然后自行发送。 | 输入「请从运营成本考虑」，选「允许管理员补录」并连续点两次「继续讨论」。原文仍在，所选方案只追加一次，执行轮次数保持原值。用户显式发送并受理后，原会话才增加一轮；同名选项不会写入另一宿主的会话草稿。 |
| FR-07 / AC-07 | 新轮受理后，先前轮次的卡片供回看。用户可以打开当时的依据；带选项进入草稿的动作只在所属会话的最新轮提供。 | 第二轮受理后从历史打开第一轮，能看到第一轮的内容、展开其依据，不能从该卡追加草稿。重开同一段历史不会再次写入草稿或发起轮次。在执行详情回看时适用同一限制。 |
| FR-08 / AC-08 | 卡片随所属助手回复出现。一段内容完整且工作台支持时才启用操作。不能呈现的部分有可读反馈；已经展示的有效内容仍可阅读。 | 回复分段到达时，未收全的卡片没有可用按钮。收到未支持的组件或无效更新时可读到反馈或原文，草稿不变。随后收到完整有效的卡片可以正常展开。 |
| FR-09 / AC-09 | A2UI 回复遵循 YSS 工作台的 UI 与可视化规范。工作台决定字体、层级、颜色、材质、组件和状态表达，Pi 与 Grok Build 仅决定允许的内容、结构、数据及动作。 | 在相同窗口大小下切换宿主，同类卡片的字体、控件尺寸、选中与焦点提示一致，卡片和输入区对齐原阅读栏。桌面、窄屏和系统辅助显示模式分别按[视觉验收对照](2026-11-28-agent-conversation-a2ui-interaction.md#视觉验收对照)复核。 |

**发送未受理时**，沿用原会话的发送规则。把选择追加到草稿后发送，若工作台明确返回未受理，仍只有原轮次，原卡保持最新，包含原文和选择的草稿可编辑。收到新轮受理结果后，原卡才转为仅可回看。发送结果待核实时，先按原会话回执核实实际轮次。此分支同时检验 AC-06、AC-07。

| 容易混淆的条件 | 对应验收 |
| --- | --- |
| 已追加的选项仍在草稿里，用户在该行末尾补写一句再点「继续讨论」 | 原有输入、已追加的内容和补写的文字均原样保留，同一个选项不再追加一份。若用户已把追加的整段删除，可重新选择并加入。即使当前运行已展示完整卡片，发送下一轮仍须满足原会话的发送条件。对应 AC-03、AC-06。 |
| 在执行详情打开会话甲的卡，主会话当前显示乙 | 详情是回看入口，可展开甲当时的依据。使用已有的「打开原会话」进入甲，再按甲当时的最新轮决定能否继续。浏览详情、跳转或加载较早一页均不会写入甲或乙的草稿。对应 AC-01、AC-06、AC-07。[执行详情入口](../../../ui/src/views/Jobs/index.vue) |
| 旧页面仍显示「继续讨论」，另一标签页已在同一会话受理了新轮 | 追加前核对来源会话及最新受理轮次。已过期的操作不能改动草稿。Pi 写有「请从运营成本考虑」时，从另一标签修改 Grok 的草稿，也不能覆盖 Pi 已保存的输入。对应 AC-01、AC-06、AC-07。 |
| 本轮的发送回执未知，用户仍在编辑 | 不重复发送，也不从资格待核实的卡片追加。核对原请求后，未受理则保留最新草稿和轮次；已受理只增加对应的一轮，轮中显示发送时的原文，核对期间新编辑的草稿保留。对应 AC-06、AC-07。 |
| 卡片尚未完整抵达，或后续更新失败，用户刷新或切走后返回 | 只回看该轮实际收到的内容。收到过有效卡就保留最后的有效画面和对应错误提示；从未收到有效卡就保留文字和接收情况。新轮开始、载入历史和重放消息都不能补出当时未出现的选项。对应 AC-01、AC-08。 |
| 用户本轮明确要求纯文字，模型仍附带有效或无效的卡片块 | 纯文字要求优先于富内容识别和错误回退。展示可读的说明、依据或方案差异，隐藏交互块及其协议原文。缺少可读内容时如实提示，并允许继续提问。下一轮按该轮的实际要求呈现。对应 AC-05、AC-08。 |

## 两个验收场景

两个场景都使用虚构的「活动报名截止后能否补报」讨论。同一份已结束的活动报名是讨论对象，用户点击卡片只作用于会话。

1. **需求澄清。** 用户问「报名截止后还需要澄清哪些问题」。在回复里查看一个问题的依据，再回到问题列表，选择想追问的一项并点击「继续讨论」。检查草稿保留该问题的含义和原有文字；此时该 Spec 的正式待答问题状态不变。
2. **方案比较。** 用户问「统一截止和允许管理员补录，怎么选」。两项可按相同维度比较，例如截止后由谁处理、运营需要承担什么工作。用户选中一项后仍可改选。按 AC-06 追加并发送，再按 AC-07 回看第一轮；换到另一宿主能走同一路径。

在[可操作原型](../../../prototypes/2026-11-28-agent-conversation-a2ui/dist/index.html)切换 Pi 或 Grok Build，打开对应的示例会话。交互动作、呈现时机、异常反馈和模拟范围见[交互说明](2026-11-28-agent-conversation-a2ui-interaction.md)。

## 接入方案与验收边界

现有 Pi RPC 和 Grok Build ACP 都把助手文字送入工作台消息流。拟在两者的助手正文中使用明确标记的 `a2ui` 块承载 A2UI 1.0 消息，工作台负责校验、渲染和处理动作。两端均需收到同一份可用组件、动作和输出示例。Pi 可从主工程发现已安装的原型技能；Grok Build 由工作台随受控上下文提供精简说明。工作台内置运行所需的显示组件，用户无需在每个会话中安装组件。

现有助手消息已支持完整的 Mermaid 和图表代码块。A2UI 可复用同一助手消息入口。用户输入、工具输出以及普通 JSON 示例保持原有显示方式。Pi 的流式片段后可能再到达最终全文，Grok 把同一作业中的助手文本连续追加。两端都应以完整且通过校验的内容为显示依据。Pi 最终全文和历史重放只更新原卡；Grok 收齐完整内容即可显示。两者都不因渲染或重放而追加草稿。联调中用两个轮次复用同一卡片标识，核对后到的旧轮内容不会替换新轮卡片。[Pi 消息处理](../../../src/workbench/pi/rpc.rs) · [Grok 消息处理](../../../src/workbench/grok/macos.rs)

卡片可携带展示数据与允许的界面动作。工作台按原消息、会话、轮次及当前资格处理这些动作，工程权限、正式答复与成果接收继续由其原入口处理。执行详情只有回看上下文，主会话持有可编辑草稿。还原历史时使用当时实际取得的内容和可核实的选择；仅有助手原文时可以恢复可阅读的选项，不能据此猜测用户当时选了哪一项。完整产品原型、任意运行模型生成的页面、跨轮改写历史回复均在本次范围之外。

产品验收应分别从 Pi 和 Grok Build 的真实入口检验文本分段、发送受理、历史回看、会话切换和只读权限。交互原型用于复验用户动作和画面结果；真实宿主、文件权限及模型输出质量仍需研发接入后验证。
