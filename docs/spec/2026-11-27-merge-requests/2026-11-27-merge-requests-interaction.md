# 合并请求浏览交互说明

工作台用户从一级菜单「合并请求」查看已接入仓库的 GitLab MR、GitHub PR。常用路径是按状态、仓库或关键字找到请求，阅读简明详情，再到原站查看文件差异、讨论或处理审批。 [主规格与验收](2026-11-27-merge-requests-spec.md)

## 查看原型

[打开可操作原型](../../../prototypes/2026-11-27-merge-requests/dist/index.html)。原型使用示例仓库和模拟平台响应，仓库来源、历史搜索、审批和 CI 的显示可在浏览器里操作验证。[打开查询与 Markdown 优化场景](../../../prototypes/2026-11-27-merge-requests/dist/index.html#performance)。

在 YSS CLI 仓库根目录运行以下命令可从源码预览。执行 `corepack pnpm@10.32.1 build` 重新生成单文件 HTML。

```sh
cd prototypes/2026-11-27-merge-requests
corepack pnpm@10.32.1 install --frozen-lockfile
corepack pnpm@10.32.1 dev
```

## 页面与操作

| 区域 | 用户看到和可以执行的操作 | 规则 |
| --- | --- | --- |
| 工作台主导航 | 「合并请求」与现有的一级入口并列。打开后汇总当前可识别的 GitLab、GitHub 仓库，落在「开放中」。 | FR-01、FR-03 |
| 仓库来源 | 核对各仓库的平台、实例、完整路径、纳入依据及读取状态。有效的产品 Home 绑定优先，其次是可识别且无歧义的 `origin`。其他远端由用户明确纳入。同一仓库的多个本地登记合并展示。 | FR-02 |
| 状态页签与查询区 | 「开放中」「已合并」「已关闭」「全部」共用标题或编号搜索、平台和仓库筛选。默认按更新时间从新到旧，可切换为创建时间从新到旧。页签数字只表示可核实的总量。 | FR-03、FR-04 |
| 结果列表 | 每行展示标题、平台、仓库及编号、作者、创建和更新时间、状态。开放中的草稿带「草稿」标记。标题打开详情。列表可继续浏览后续页，历史没有固定截止日期。 | FR-03、FR-04、FR-05 |
| 只读详情 | 请求标题旁显示仓库与编号，并列出作者、源分支、目标分支、创建和更新时间以及适用的合并时间。变更说明下分别展示审批和检查或流水线。可用的「在原站打开」指向同一条请求。 | FR-05 |
| 刷新与失败 | 手动刷新保留当前筛选。某仓库连接或查询异常时，其余来源继续可用。提示指出受影响仓库及原因，并提供重试。 | FR-06 |

桌面保留工作台浅色导航与内容排版。窄屏缩为图标导航，标题与元信息允许换行，筛选和页签按宽度重新排列。详情是独立滚动的阅读层，关闭或按 Esc 回到列表原位置，继续使用原筛选和页码。键盘焦点回到打开详情的标题控件。

## 查询与描述阅读优化

沿用 YSS 工作台的表格、页签、抽屉和加载反馈。加载提示和仓库覆盖情况放在现有结果区，用户可以继续操作已能确认位置的行。进入其他状态或更换搜索条件时，新的筛选和加载状态立即生效。等待更早的历史、准确总数或单个摘要时，正文和已有结果仍保持可读。

| 操作 | 画面及反馈 | 验收 |
| --- | --- | --- |
| 进入「开放中」，部分仓库仍在读取 | 先显示位置已确定的请求。其余来源仍在核对时，显示覆盖进度；总数未知时省略。用户可以打开已展示的请求。 | AC-08 |
| 某仓库读取失败，或用户点击重试 | 提示仓库和原因，保留其他来源的可读结果。部分结果不会显示为完整总数或「无匹配」。重试该仓库后按原条件补齐，已读结果在仍适用时保留。 | AC-06、AC-08 |
| 搜索 `#248`、`!248` 或标题片段，再快速更换条件 | 精确编号只显示对应平台和仓库内的匹配。按标题找较早结果时，范围尚未读全有提示。旧响应不更新现在的列表、计数和焦点。 | AC-04、AC-09 |
| 打开示例 GitLab `!248` | 抽屉立即显示仓库、编号及标题。基础详情随后出现，原站入口及可读描述可用；评审和当前 CI 分区显示自己的读取状态。 | AC-10、AC-11 |
| 阅读描述、重试评审、展开历史 CI | 标题、列表、表格和代码按工作台排版。评审失败时可在该区重试。点击历史 CI 后才读取旧记录，返回的记录标明适用提交或流水线。 | AC-10、AC-11 |
| 在加载期间关闭抽屉，或切换到另一条请求 | 关闭后回到触发的列表行。旧请求晚到的描述、评审和历史 CI 不替换另一条请求的内容。发现访问被撤销后，隐藏已失效的列表与详情。 | AC-05、AC-07、AC-10 |

Markdown 的外站网页链接由用户主动打开。仓库相对链接、本机地址、工作台控制链接保留可读文字，远端图片显示占位。内嵌 HTML 以文字显示。桌面和窄屏均保持标题层级、对比度和清晰焦点。长代码、表格在正文内部滚动。浏览器和桌面 WebView 的导航行为分别复验。[现有 Markdown 渲染规则](../../../ui/src/views/SpecDetail/schemas/markdown.ts) · [工作台界面规范](../../../ui/DESIGN.md)

## 状态与恢复

| 条件 | 可见结果 | 后续操作 |
| --- | --- | --- |
| 首次读取 | 列表区域显示加载反馈，状态页签暂时没有总数。 | 顺序已确认的结果可先浏览。 |
| 仓库已读取，当前条件无匹配 | 显示当前筛选无结果。 | 清除搜索或筛选，或切换状态。 |
| 没有可查询仓库 | 说明还没有能读取的仓库来源。 | 查看仓库来源，核对已登记工程及远端。 |
| 部分结果未完成 | 显示已读取的结果，指出受影响仓库。暂时无法核实的总数留空。 | 重试失败仓库或缩小查询范围。 |
| 同范围刷新时发生临时读取失败 | 如有上次成功结果，可标出读取时间和过期提示。 | 重试后以本次可核实结果更新列表。 |
| 访问被拒绝 | 该来源内容不可读，保留其他仓库结果。 | 核对本机对应实例的授权后重试。 |
| 单条审批或 CI 不可读 | 详情保留可读字段，受影响区说明读取状态；平台已确认的流水线失败仍以状态显示。 | 临时失败可在该区重试。权限或字段不可用时，可在原站按当前身份查看。 |

「在原站打开」显示模拟原站和目标地址。独立打开原型时使用新标签页，在工作台预览中可从模拟原站返回同一条详情。生产环境沿用本机工作台已有的 GitHub、GitLab 连接，实际自建实例、凭证权限、平台分页和限流行为由真实环境验收。 [工作台连接说明](../../workbench.md#工程维护与产品-home)

## 原型评审场景

从「原型场景」切换到指定场景，或在单文件原型地址后加入口片段。「重置场景」恢复该场景的初始条件。仓库名称、作者及记录内容均为示例。

| 场景 | 操作 | 核对 |
| --- | --- | --- |
| 正常读取 `#normal` | 在「开放中」同时查看 GitLab `!248` 和 GitHub `#248`。输入 `248`，再分别输入 `!248` 和 `#248`。按平台、仓库筛选并切换排序，翻页后打开、关闭详情。 | AC-01、AC-03、AC-04。两个仓库的同号记录可区分，查看详情后可接着浏览。 |
| 正常读取 `#normal` | 进入「已合并」，搜索 `#31`；再进入「已关闭」，确认该记录消失。 | AC-03、AC-04。2026 年 4 月的已合并记录仍可检索，已合并与已关闭分别归类。 |
| 正常读取 `#normal` | 打开「仓库来源」，核对 Home、`origin` 和待确认来源。将 `nebula/ui-components` 纳入并保存，搜索「键盘操作」，再撤回。 | AC-02。手动纳入和撤回影响浏览范围，同一远端的多个工作树归到一个仓库。 |
| 正常读取 `#normal` | 打开 GitLab `!248`，查看说明、分支和两个独立的状态摘要，再选择「在原站打开」。 | AC-05。模拟原站展示对应平台、仓库与编号的原链接。 |
| 部分仓库读取失败 `#partial` | 查看成功结果与失败仓库提示，重试失败来源。 | AC-06。查询范围仍可辨认，恢复后重新显示可核实的计数。 |
| 平台限流 `#rate` | 查看受影响的来源和限流提示。 | AC-06。区分平台限制和完整读取后没有匹配。 |
| 授权失效 `#auth` | 核对失败仓库的内容隐藏，并查看其余可读取结果。 | AC-07。无权访问和零条结果分别显示。 |
| 未登记工程 `#empty` | 打开列表及「仓库来源」。 | AC-07。说明需要先登记并启用工程。 |
| 查询优化 `#performance` | 等待快慢来源逐项返回，在慢来源完成前查看已经确认的行。读取失败后重试该仓库，再切换编号条件并返回。 | AC-08、AC-09。排序依据尚未齐备的条目与总数保持待核对，已验证行仍可打开。 |
| 查询优化 `#performance` | 打开 `!248`，先阅读 Markdown，再重试评审、展开历史 CI。用 Esc 关闭并检查焦点。 | AC-10、AC-11。各区分开反馈，桌面与窄屏均能阅读，历史 CI 对应提交。 |

## 11 月 27 日原版复核

- 冻结依赖安装、Vue 类型检查与 Vite 构建通过，产出可离线打开的单文件 HTML。
- Chrome 中实测桌面聚合列表、平台与仓库筛选、排序和翻页、同编号区分、历史编号搜索、详情及原站模拟、额外远端纳入和撤回、部分失败重试、授权失效与未登记工程。390 × 844 下没有页面横向溢出，验证键盘进入详情、Esc 关闭和回到原行。窄屏列表的 axe 自动检查未报告匹配检查规则的违规项。

- 原型用本地样例演示查询与失败恢复。真实平台的多仓分页完整性、权限变化和并发回包、历史审批与 CI 的适用判定、同查询旧数据的新鲜度留待研发联调验收。左侧其余工作台菜单仅用于展示入口位置。
