## 目标与范围

工作台用户从一份 Spec 发给 Pi 一项任务，查看 Pi 的答复和执行步骤，回应执行中的业务问题，并在核对差异后决定接收哪些文件。完成一轮后，用户可沿原 Pi 会话补充要求，连续阅读前后几轮并追溯每轮执行。切换到产物、日志或另一会话后，用户能判断当前内容来自哪份 Spec、哪个会话和哪一轮。

当前工作台已支持从 Spec 启动 Pi、流式显示本轮、本机模型选择与诊断、隔离工作区、同会话续接和文件接收。续接会打开新的一轮执行详情，前后轮通过链接访问。草案建议新增连续会话视图，让输入、执行、答复和成果在同一工作区内可达。现有行为以 CLI 3.17.1 源码 `13374bb` 为基线。 [工作台运行说明](../../workbench.md#在工作台运行-pi-agent)

首版以已登记、启用的 Spec 为任务入口，交付同一会话内的执行及成果审阅，包含待处理会话、执行活动分组和差异选行返工。按参考图使用黑白灰布局。桌面左侧为窄图标栏与会话列表，顶部显示当前会话、运行设置和摘要入口，右上是会话摘要，成果通过抽屉审阅。对话与底部输入同宽居中，组件采用 shadcn-vue AI Elements。工程维护类作业及既有 Codex 记录沿执行记录访问。 [交互布局](2026-11-25-pi-agent-workspace-interaction.md#页面组织) · [AI Elements](https://shadcn-vue.com/docs/ai-elements)

可编辑的下一轮队列作为下一批单独评审，范围见 FR-07。任意目录聊天、运行中追加普通指令、修改 Pi 全局配置、审核每条命令、自动接收、PR/MR 和发布列为后续独立范围。 [下一轮队列设计](2026-11-25-pi-agent-workspace-design.md#4-下一轮队列)

## 业务对象

| 对象 | 用户用于判断的信息 |
| --- | --- |
| Spec | 原任务依据及主工程。会话入口可返回原 Spec。 |
| Pi 会话 | 同一 Spec、同一批参与工程、同一隔离工作区下的多轮工作。历史按会话组织，模型可按轮选择。 |
| 执行轮次 | 一次发送产生的一轮作业，含要求、状态、模型、当轮命令授权、答复、工具活动和可查看的成果。保留逐轮执行记录。 |
| 本次产物与文件变更 | 某一轮生成的可读产物和已留存的差异。接收是把审核选中的文件写入原工程，由用户单独执行。 |
| 差异引用 | 用户从最新可审阅文本差异选出的行段。引用归属同一会话，记录来源工程及绑定、相对路径、差异侧和行范围、片段、成果轮次与版本，并随下一轮要求发送。 |

## 功能规则

### FR-01 从 Spec 进入或恢复会话

在启用的 Spec 中使用「运行 Pi Agent」，打开该 Spec 的 Pi 会话工作区。用户可从当前 Spec 的历史恢复会话，也可新建会话。打开某轮旧 Pi 执行链接时应定位其来源会话和轮次，可跳回最新轮。历史条目显示任务标题、最近状态和时间。首次发送成功受理后才出现新执行记录。归档、来源丢失、无可用历史和读取失败各有可见反馈，已留存内容可在既有可读范围内查看。

左侧「待处理」筛选当前 Spec 中的会话，覆盖待答复、答复保存失败、需恢复、已中断、运行失败及仍有可审阅成果未接收的情况。同一会话只计一次，点击提示定位实际轮次、问题、错误或成果，并显示可用的下一步。已受理但尚未确认保存的答复显示「保存中」。记录尚未核实时提示刷新，避免误清待办。下一批增加需用户处理的暂停队列。 [提示判定和跳转](2026-11-25-pi-agent-workspace-design.md#待处理会话)

会话条目支持单独删除。确认时显示会话名称及待审阅文件数量。删除移除该会话的工作台对话、各轮执行记录、日志和成果入口，保留工程文件、隔离工作区、Pi 本机会话文件及已写入 Spec 的内容。会话运行、接收或等待事务核实时暂停删除。确认后若出现新轮次，须重新核对后确认。

### FR-02 在发送前确定运行范围与模型

新会话展示原 Spec、固定的主工程、可选的已登记参与工程以及逐工程带入的未提交文件。各工程须有可用 Git HEAD。主 Spec 尚未进入 HEAD 时，须显式带入其相对路径。执行基于隔离 worktree，用户可在提交前核对工程与文件范围。任务必填且接受现有长度校验，启动拒绝时保留任务和已选设置。

模型默认按本机 Pi 启动设置确定。新会话可按供应商及名称搜索本机 Pi 返回的候选，选择本次使用的模型，再切回 Pi 默认。模型区呈现供应商、模型和本机检查结果。平台、Pi 版本、沙箱、模型或本机凭证未就绪时给出原因及可用处理路径。默认模型不可用时，选择器仍可打开。启动前重新核对当前模型，变化时保留输入并要求重新检测或明确选择。

模型选择器列出 Pi 为该模型提供的推理级别。用户可选择本轮级别，开始后对话显示 Pi 实际使用的模型与级别。续接时沿用同一模型仍支持的历史级别，换模型后按新模型的选择和可用级别运行。

「测试模型连接」由用户主动发起，在隔离临时环境发送固定短消息，界面提示可能消耗少量额度。测试期间暂停发送任务。测试结果与本机预检分别展示。已知套餐、访问权限或配置问题需要先处理。暂时性连接故障提示重试，发送资格仍按当前有效预检与故障类型判断。

运行设置提供「编辑工作区」和「只读分析」。编辑模式可修改隔离文件，命令授权按轮生效，默认关闭。开启后执行离线命令，沿用工作台沙箱限制。只读模式开放读取、搜索、报告计划和已登记问题，可在答复中提出建议。页面展示当轮模式和命令授权，续接时可重新选择。 [现有 Pi 运行约定](../../workbench.md#在工作台运行-pi-agent)

### FR-03 在对话中观察及控制当前执行

按轮排列用户要求和 Pi 可见答复。工具、命令、文件活动依发生顺序置于所属轮次，可按需展开名称、状态、输出、退出码和脱敏错误。原始事件及宿主信息仍可从该轮执行详情查阅。当前会话可展示的内容由实际留存事件决定，过往未记录的要求或正文提示缺失。

Pi 返回用量时在本轮展示估算用量与实际上下文窗口。Pi 推理、更新执行计划或压缩上下文时显示实际状态，命令执行期间可展开已返回的输出。重新打开会话可读取已留存的状态。成果保存后，对话中的「本轮成果」可打开对应快照，文件变更按工程和相对目录分组。

同一轮内连续的普通活动可折叠成一组，展开后仍按实际顺序显示。分组统计操作次数，两次独立读取同一文件计两次。用户消息、Pi 正文、问题、错误及轮次结束切断分组，失败项和待答复保留独立入口。命令开始与结果更新同一活动项，重连或分页遇到已载入活动时只显示一次。有可定位的成果轮次和工程时，文件活动可以直接打开对应差异。 [活动分组说明](2026-11-25-pi-agent-workspace-design.md#执行活动分组)

阅读最新内容时跟随流式输出。用户上翻、加载较早记录或主动查看特定轮次时保住阅读位置，并提供返回最新入口。页面重新加载或重新连接后恢复可获取的会话与本轮状态。连接中断时显示最近已知内容和连接状态，避免把浏览器离线解释为作业停止。

执行状态包括准备或排队、运行中、待答复、正在停止、已结束、失败、已停止、已中断和需恢复。「正在停止」表示已收到停止请求，实际终态由作业返回。停止只作用于当前作业，已留存消息和工作区按既有保留规则可供继续核对。「已结束」表示该轮执行结束，成果是否符合 Spec、是否已核对或已接收由各自结果显示。

### FR-04 在原轮答复 Pi 的业务问题

Pi 发出业务问题时，在同轮对话插入问题、选项、可选自填及提交动作，其他视图可定位待答位置。提交时防止重复。请求未受理且问题仍待答时，保留填写并允许重试。请求已受理但保存失败，或问题已失效时，保留填写供用户参考，显示实际状态及刷新路径。只有保存成功才标记已答复，记录可追溯实际答复，原轮继续执行。业务答复的采纳、Spec 正文变更及内容确认沿工作台原有规则处理。 [工作台答复与回写](../../workbench.md#在工作台运行-pi-agent)

### FR-05 在同一 Pi 会话中继续下一轮

本轮达到终态并且原 Pi 会话、隔离工作区、来源与所选模型有效时，底部输入可开启下一轮。续接沿用原 Spec、参与工程和隔离工作区，默认沿用会话记录的模型。点击输入区模型名可从本机 Pi 候选切换下一轮模型。工作台在发送前核对所选模型，保留会话历史和 Pi 默认配置。模型暂不可用、工作区丢失或来源不满足续接条件时显示原因并保留草稿。用户可改选模型、恢复原工作区或从原 Spec 新建会话。改变参与工程时使用新会话。排队、运行、待答复或正在停止期间可编辑下一轮草稿，发送等待本轮结束。通过旧轮链接进入时，续接资格仍以该会话最新轮为准。

在同一会话的最新可审阅文本差异中，用户可选中运行起点侧或隔离结果侧的连续行段，添加意见并放入下一轮草稿。原工程当前侧用于三方核对，二进制显示摘要。用户显式发送时核对引用的成果版本、来源工程绑定及续接前提。任一项失效则拒绝本次提交并保留草稿，用户可重新引用、移除失效引用或恢复续接条件。添加引用和发送返工请求只影响会话与隔离工作区，原工程文件在用户后续接收时写入。 [返工流程](2026-11-25-pi-agent-workspace-design.md#3-从差异行返工到接收)

### FR-06 就地审阅和接收隔离成果

成果区标明内容所属轮次，展示可读产物、文件变更、目标工程及接收状态。选择文件后可核对运行起点、原工程当前内容和隔离结果。二进制文件显示可取得的差异摘要。旧轮可回看已留存的消息和文件活动，有该轮成果快照时可预览。快照缺失时说明原因并指向最新成果。

判定待接收改动时，同一 Pi 会话、同一可信工程绑定及路径已有接收记录的，以最近实际接收的版本为比较基准。版本也可为「已接收删除」。工程重绑前的接收记录仅供回看。确认当前绑定没有适用记录时，以运行起点为基准。来源或接收版本无法核实时提示核对并阻止接收。

隔离结果相对基准有变化时，纳入本轮待审阅差异。第一轮接收了新增文件，下一轮隔离结果删除该文件时，仍须列出删除。原工程当前内容偏离基准且与隔离结果不同时，显示冲突，即使原工程已被用户改回运行起点。原工程当前内容与隔离结果一致时，显示「内容一致，无需写入」。只有存在实际接收回执才显示「已接收」。隔离结果仍等于基准时，原工程的单独变化不产生新的 Pi 待接收改动。

最新轮结束并且受支持的成果可审阅时，用户可逐个勾选已经核对的文件，再主动接收。接收前显示目标工程和所选文件。原工程在审阅后变化时，拒绝过期选择，更新差异并要求重新核对。当前版本仍有冲突时，用户须明确同意使用该隔离结果更新文件。多工程分别显示接收结果，可针对未接收项继续处理。包含主 Spec 或关联附件时，继续核对真实答复 ID 与适用范围。接收成功后可返回原 Spec 核对采用的内容和工作台记录。 [现有成果接收规则](../../workbench.md#在工作台运行-pi-agent)

以实际事务结果区分「未发生写入」「已回滚」「需恢复」「已提交待清理」。前两类可重新审阅并重试对应项。「需恢复」按实际写入的 Git 根进入「工程维护 → 恢复未完成事务」，恢复前暂停涉及该工程的接收与续接，恢复后重新核对。「已提交待清理」先处理清理并核实接收台账。其他工程实际已接收的结果保留。接收超时或台账保存失败时显示「结果待核实」，先核对实际文件和回执，再决定是否还有待接收项。关闭再打开成果抽屉时，同一轮的核对依据与接收记录继续对应其实际版本，写入前的核对材料标明「接收前原工程内容」。 [接收结果说明](2026-11-25-pi-agent-workspace-design.md#3-从差异行返工到接收)

### FR-07 下一批 · 管理同一会话的下一轮队列

用户显式把要求加入下一轮队列后，待发送项按会话保留，可编辑或移除。已有待发送、暂停或待核实的队首时，普通发送保留为草稿，用户可编辑队首、恢复队列或移除相关排队项。入队前已受理的轮次继续执行。只有前一轮成功结束、确认无待答复及未接收成果、引用与续接条件均有效时，才按顺序自动派发。自动派发沿用当轮离线命令默认关闭的规则。

前轮停止、失败、需恢复、工作台重启或派发结果不明时，暂停优先于自动派发。工作台核实已受理状态后由用户显式恢复。已有作业时定位原作业，待发送项每次只产生一次受理。前轮仍有待接收成果时，队列暂停。用户可先接收并核实已清除待审阅条件，再显式恢复队列，也可明确选择继续队首，将未接收的隔离改动留到新轮重新审阅。 [队列状态与恢复](2026-11-25-pi-agent-workspace-design.md#4-下一轮队列)

| AC-07 · FR-06 | 进入成果区读产物和差异，单选审阅后的文件并显式接收。页面显示目标及接收结果，未选文件留在隔离成果中，执行结束本身不会写入原工程。 |
